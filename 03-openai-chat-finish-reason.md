# OpenAI Chat Completions finish_reason

Chat Completions sets `finish_reason` on each choice to `stop`, `length`, `tool_calls`, `content_filter` or the deprecated `function_call`.

The reference, in full:

> The reason the model stopped generating tokens. This will be stop if the model hit a natural stop point or a provided stop sequence, length if the maximum number of tokens specified in the request was reached, content_filter if content was omitted due to a flag from our content filters, tool_calls if the model called a tool, or function_call (deprecated) if the model called a function.

## Two things the value does not tell you

**A refusal is not a finish_reason value.** It arrives in the message's own `refusal` field, which the reference describes as "The refusal message generated by the model." So a `stop` can still carry a refusal. Check `message.refusal` before you read `message.content`.

**Each choice stops on its own.** The `choices` list "Can be more than one if n is greater than 1", and every choice carries its own `finish_reason`. Check each one, not only `choices[0]`.

## What your code should do (house recommendations)

The reference gives no action for these values. The table below is this repo's recommendation, not OpenAI's.

| Value | Recommended |
|---|---|
| `stop` | Check `message.refusal`; if empty, use the content. |
| `length` | The output is truncated. Do not parse it as JSON or as a complete answer. Retry with more room or continue. |
| `tool_calls` | Run the tools and send the results back. |
| `content_filter` | Content was omitted. Show the user that something was withheld. Do not retry the same input blindly. |
| `function_call` | Deprecated form of a tool call. Handle it like `tool_calls`, and plan to move to tools. |
